# 实验与决策记录

近期的写层回收、跨 worker 缓存和 OpenHands 三种租约策略数据见 [Coding agent 的 worker 复用实验](worker-reuse.md)。

## 独立仓库内可以复现的结果

集成测试用本机 Docker/OrbStack 和 OpenHands SDK 1.59.0。A 写入工作区、`/tmp` 和 `/root`，启动后台服务，并在同一租约的第二条命令确认它仍可用。归还后 B 获得同一个 worker，能运行预装依赖，看不到 A 的私有文件，也连不上旧服务。A 的工作区写入仍在。测试还验证重叠工作区拒绝、两个并发租约触发 **1 → 2 → 1** 的伸缩，以及外置 agent 的固定 SDK 工具调用。单次真实模型修复见 [DeepSeek Flash 观测](agent-observation.md)。

仓库的 `benchmarks/` 保存独立的单 worker 交接实验。两组使用同一已缓存的 Python 环境，交错执行 12 轮。

| 方案 | A 完成至 B 首条验证命令完成，P50 | A 启动至 B 首条验证命令完成，P50 |
|---|---:|---:|
| 删除 A 的容器，用同一热镜像启动 B | 147 ms | 274 ms |
| 保留 worker，重建可写层和进程空间 | 43 ms | 93 ms |

热 worker 首次准备约 1.61 秒，包含导出和复制基础文件系统，未计入表格。每轮验证预装依赖、文件残留和旧后台服务。测试使用固定命令，不测 LLM、排队或动态扩缩容，也没有证明隔离强度等价。基准脚本依赖旧实验镜像标签，示例镜像需要重打标签或调整脚本的 IMAGE 常量后才能重跑；现有 JSON 对应原镜像。

## 下载期间归还租约的对照

从仓库根目录运行 `PYTHONPATH=. python benchmarks/sandbox-io-offload.py --rounds 12 --delay 1`。脚本使用已构建的 `sandweaver-demo:local`，只启动一个 Docker worker，无需 OpenHands SDK 或公网。两组都由独立的 I/O 线程池向本机 HTTP 源下载同一个产物。两组的租约策略分别是持有和归还。归还组重新领租约后，验证私有文件已清除，且工作区文件和下载产物可用。

短任务的领租约耗时从发出请求计到确认成功，包含排队和建立任务视图。下载任务的总耗时从第一次领租约请求计到最后归还完成。租约持有耗时只累计领到租约至确认归还的区间，重新领租约的成本单独记录。镜像导出和首次 worker 准备单独计时。脚本先为每组预跑一轮，再交错测量，并输出原始样本。

一次本机 OrbStack 运行中，HTTP 源固定等待 1 秒后返回 20 字节。每组测 12 轮，镜像导出和 worker 准备耗时 1.93 秒，单独记录。

| 指标 | 持有租约等待 | 下载期间归还 |
|---|---:|---:|
| 短任务领到租约，P50 / P95 | 1141 / 1221 ms | 51 / 55 ms |
| 下载任务租约持有时间，P50 | 1115 ms | 105 ms |
| 下载任务总耗时，P50 | 1165 ms | 1244 ms |
| 下载后重新领租约，P50 | 无 | 78 ms |

12 个样本的最近秩 P95 等于最大值。这组对照刻意安排两个任务竞争同一个 worker，测量范围限于合成的下载等待和租约交接。真实负载里能拆出的等待比例，以及何时据此预热或扩缩池，仍待验证。

### I/O 池预热和短任务到达时机

这轮额外测试了在首次领租约前启动 I/O 线程并连接已知 HTTP 源。该选项已从脚本移除，当前统一在提交下载时启动线程和连接。历史对照使用本机 TCP，无 DNS、TLS 或跨轮连接复用。

同一 demo 镜像和单 worker 下，每个设置两组各测 6 轮，另各预跑 1 轮。下表为中位数，单位为毫秒。

| HTTP 源等待 / 短任务到达偏移 | I/O 池 | 短任务领租约（持有 → 归还） | 下载任务总耗时（持有 → 归还） |
|---|---|---:|---:|
| 1000 / 0 | 按需 | 1137 → 51 | 1162 → 1246 |
| 1000 / 0 | 预热 | 1138 → 49 | 1163 → 1235 |
| 30 / 0 | 预热 | 137 → 50 | 163 → 310 |
| 1000 / 1200 | 预热 | 62 → 56 | 1162 → 1247 |

本机 I/O 线程启动与 TCP 预连接的中位成本约 0.3 毫秒。固定 1 秒等待时，两种连接策略的下载中位数都约为 1.007 秒，未观察到预热带来明确改善。30 毫秒场景下短任务更早获准运行，但下载任务重新领租约时需要与它竞争。短任务在下载及租约清理之后才到达时，归还策略对短任务的收益接近消失。

### 动态归还

当前脚本把下载写入工作区根目录以外的任务专属暂存区。下载完成并持有工作区租约后，先验证产物内容，再在同一文件系统上用原子重命名发布。临时目录退出时清理。以下历史计时来自直接写入工作区的版本，暂存发布修正后需要重新测量才能作性能对照。

加上 `--dynamic-threshold 0.1` 会增加第三组。当前步骤结束时，若另一个任务已就绪且预计下载至少需要 100 毫秒，动态组才归还租约。实验固定一个 worker，因此另一任务就绪时确实有容量竞争。默认让短任务在租约决策前就绪；正值 `--probe-offset` 让短任务在源收到 GET 后再等待指定秒数。新版在租约决策后立即提交下载，下载可以与归还重叠。

等待估计直接使用合成源的配置延迟，属于理想化输入。这个实验比较决策规则，尚未测真实延迟预测、多个等待任务或下载完成后的集中回流。

本机 OrbStack 使用同一 demo 镜像，每个场景固定一个 worker，三种策略轮换顺序，各测 6 轮并各预跑 1 轮。复现时传入 `--rounds 6 --dynamic-threshold 0.1`，再分别选 `--delay 1`、`--delay 0.03` 和 `--delay 1 --probe-offset 1.2`。

| 场景 | 动态组归还次数 | 短任务领到租约的 P50（持有 / 归还 / 动态） | 下载任务总耗时的 P50（持有 / 归还 / 动态） |
|---|---:|---:|---:|
| 1 秒下载，短任务立即就绪 | 6/6 | 1136 / 79 / 76 ms | 1162 / 1222 / 1219 ms |
| 30 毫秒下载，短任务立即就绪 | 0/6 | 141 / 76 / 139 ms | 168 / 310 / 164 ms |
| 1 秒下载，短任务晚到 1.2 秒 | 0/6 | 68 / 55 / 70 ms | 1159 / 1216 / 1159 ms |

## 早期实验提供的线索

以下来自独立仓库建立之前的本机实验。配置和计时边界不同，数字不应横向拼接为同一个 benchmark。

| 探索 | 观察与决策 |
|---|---|
| 原生 OpenHands 对照 | 使用完整 Agent Server 的官方 Docker 路径作系统对照；外置 SDK、按需依赖构建和缓存分别作为候选路径。27 批交错的小型 Node/Python 对照中，双项目请求到末次测试完成 P50 约为 6.44 s（原生）、1.62 s（外置冷项目环境）、398 ms（外置缓存环境）。基础镜像已热，冷项目可能复用包下载缓存。差值包含架构和缓存，不能全部归因于预热。 |
| 会话内环境切换 | Node → Python → Node 固定任务序列，三组 P50 约为 4.62 s（完整 Agent Server，单容器）、264 ms（外置 agent，单容器）、682 ms（外置 agent，强制切换）。复用兼容环境优先于强制切换。 |
| 用完即销毁的池 | 连续到达 2/5/10 请求每秒时，特定测试里的命中率约 100%/90%/20%。高负载下补位追不上，额外成本可能让池比按需启动更慢。这促成了原 worker 归还接力。 |
| 预热依赖与预测 | 从固定预热探索到关键词、历史转移和混合策略。特定 pandas/humanize 工作负载可以从预初始化受益，不能外推到一般 coding task。实际小样本还观察到纯模型任务也可能付出无用的准备成本。默认使用真实请求和已知环境，不把预测放进正确性路径。 |
| 共享基础层和包缓存 | Docker 镜像层可共享，容器有自己的 COW 写层。早期 BuildKit 缓存 pip/npm 下载；已安装依赖环境另外缓存。仅缓存包仍需安装，缓存成品可以省安装但更占盘、也更容易因输入变化失效。 |
| 浏览器与后台服务 | 浏览器的 cookie 和 DOM 可以暂时留存，容器重建后原服务的内存登录状态仍会丢失。工作区文件保留与进程状态恢复是两件事。 |
| CRIU / Firecracker | OrbStack 上的最小 CRIU checkpoint 在 dump 阶段失败。没有完成 Firecracker 快照实验。当前实现采用新的可写层和进程空间，不依赖快照。 |

原生 OpenHands Canvas 与当前 SandWeaver SDK 客户端是不同入口。Canvas 的原生执行后端没有被替换。完整系统基准应保留原生 OpenHands，机制基准应固定 agent、环境和任务，仅更改归还策略。

## 真实 agent 时间线观测

一次 OpenRouter GPT-4.1 mini 运行，在临时工作区修复区间合并函数，要求处理重叠、相接、无序输入、空输入以及输入不可变。Agent 完成后，独立重跑五项测试全部通过。客户端使用 OpenHands SDK 1.59.0，worker 使用本地 demo 镜像。

该次运行从客户端开始观测到归还租约约 10.46 秒。租约确认取得至归还完成约 10.41 秒，7 次模型客户端调用合计 9.84 秒，6 次 shell 调用往返合计 0.332 秒。模型客户端区间包括网络、SDK 和重试开销，占租约持有时间约 94.5%。这里没有测量 CPU 空闲、后台进程或可安全回收状态，不能直接把这个比例解释为可节省资源。模型调用前的 Python 启动与 SDK 导入也未计入。

这是单次小型任务的观测，尚未测跨任务分布、队列竞争和前端信号的调度收益。SDK 本次未成功计算模型费用。

后续 DeepSeek Flash 单次观测已整理为[独立实验报告](agent-observation.md)，包含时间线与证据边界。该次租约 14.328 秒，模型客户端调用 13.776 秒，shell 往返 0.346 秒；不可将两次不同模型的单样本当作性能排名。
